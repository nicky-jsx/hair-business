# Stylist Marketplace — UI/UX Design System

## 1. Product Feel

The app is a premium, modern beauty marketplace where customers discover, compare, review, and book hair and beauty stylists.

The overall experience should feel:

- Premium
- Modern
- Clean
- Trustworthy
- Warm
- Stylish
- Photography-led
- Easy to use

The app should feel like a polished consumer product, **not a generic SaaS dashboard**.

Prioritise visual quality, simplicity and ease of booking.

---

## 2. Design Principles

### Photography First

Stylist and portfolio photography is one of the most important parts of the product.

Use large, high-quality images wherever appropriate.

Avoid making the interface overly text-heavy.

### Simple Decisions

Customers should quickly understand:

- Who is this stylist?
- What do they specialise in?
- Where are they located?
- How highly rated are they?
- How much do they charge?
- When can I book?

### Premium but Approachable

Avoid excessive gradients, neon colours, excessive shadows, or overly complicated UI.

The design should feel expensive without feeling intimidating.

### Mobile First

The primary experience is mobile.

Design for touch first, then scale up for desktop.

---

# 3. Colour System

Use a restrained colour palette.

### Background

Use a warm, subtle off-white/light neutral as the primary page background.

### Primary Text

Use a very dark neutral rather than pure black.

### Secondary Text

Use muted grey for supporting information.

### Brand Accent

Use one distinctive accent colour consistently throughout the product.

The accent should be used for:

- Primary buttons
- Selected filters
- Important actions
- Active navigation
- Links
- Key highlights

Do not use the accent everywhere.

### Borders

Use very subtle neutral borders.

Avoid heavy outlines.

---

# 4. Typography

Use a modern, highly readable sans-serif font.

Typography should have a strong hierarchy.

### Page Heading

Large, bold and confident.

### Section Heading

Medium-large and semibold.

### Card Title

Strong enough to immediately identify the stylist.

### Body Text

Comfortable line height and easy readability.

### Metadata

Smaller and muted.

Examples:

Location, number of reviews, service duration and other secondary information should never compete with the main content.

---

# 5. Spacing

Use consistent spacing throughout the application.

Prefer generous whitespace rather than filling every available space.

Cards and sections should breathe.

Avoid cramped interfaces.

Use a consistent spacing system rather than arbitrary margins.

---

# 6. Border Radius

Use moderately rounded corners throughout the interface.

Cards, buttons, inputs and image containers should feel cohesive.

Do not use extremely rounded "bubble" components unless there is a clear reason.

---

# 7. Shadows

Use shadows sparingly.

Most cards should rely on:

- Background contrast
- Subtle borders
- Small amounts of elevation

Avoid large, dramatic shadows.

---

# 8. Buttons

Buttons should be clear and easy to tap.

### Primary Button

Used for:

- Book appointment
- Confirm booking
- Important actions

Should have strong visual prominence.

### Secondary Button

Used for:

- View profile
- Edit profile
- Secondary actions

Should be visually quieter.

### Destructive Button

Used for:

- Delete
- Cancel

Should clearly communicate that the action is destructive.

Buttons should have comfortable touch targets on mobile.

---

# 9. Navigation

The customer experience should have simple navigation.

Avoid excessive navigation options.

Potential primary navigation:

- Discover
- Bookings
- Saved
- Profile

The navigation should remain visually lightweight.

On mobile, use a bottom navigation bar where appropriate.

---

# 10. Home / Discover Page

The discover page is one of the most important screens.

The user should immediately be able to search for a stylist.

### Top Area

Include:

- Friendly heading
- Search bar
- Location
- Quick category filters

Example:

"Find your next stylist"

Search:

"Search styles, services or stylists"

### Category Navigation

Use horizontally scrollable categories on mobile.

Examples:

- Braids
- Natural Hair
- Locs
- Colour
- Cuts
- Extensions
- Barber
- Makeup
- Nails

Do not overwhelm the user with too many categories.

### Recommended Stylists

Show visually appealing stylist cards.

---

# 11. Stylist Cards

Stylist cards should be highly visual.

Recommended structure:

Large portfolio/profile image

Then:

**Stylist Name**

★ 4.9 · 126 reviews

Speciality · Location

From £XX

Book / View Profile action

Important information should be visible without opening the profile.

Avoid stuffing cards with too much information.

---

# 12. Search Results

Search results should feel clean and easy to scan.

Allow users to:

- Search
- Filter
- Sort

Useful filters include:

- Location
- Category
- Service
- Price
- Rating
- Availability

Filters should be easy to use on mobile.

Use bottom sheets or modal filters where appropriate.

---

# 13. Stylist Profile

The stylist profile is a core product screen.

It should feel premium and photography-led.

### Header

Large profile/portfolio image.

Show:

- Stylist name
- Rating
- Review count
- Location
- Main speciality

### Portfolio

Use a visually appealing photo grid or gallery.

Photography should be prominent.

### About

Short stylist biography.

Keep the initial text concise and provide an option to expand if necessary.

### Services

Display services clearly.

Each service should show:

- Service name
- Price
- Duration

Example:

Braids
£80
2h 30m

### Reviews

Show:

- Average rating
- Review count
- Individual reviews
- Reviewer information
- Date

Keep reviews readable and easy to scan.

### Booking

The booking action should always be easy to find.

On mobile, consider a sticky bottom booking button.

Example:

**Book Appointment**

---

# 14. Booking Experience

Booking should feel extremely simple.

Recommended flow:

1. Select service
2. Select date
3. Select available time
4. Enter customer details
5. Review booking
6. Confirm

Avoid unnecessary steps.

Show:

- Service
- Price
- Duration
- Date
- Time
- Stylist

before confirmation.

The customer should always know exactly what they are booking.

---

# 15. Booking Confirmation

After booking, show a clear confirmation screen.

Include:

- Success message
- Stylist
- Service
- Date
- Time
- Price
- Booking reference if applicable

Provide clear options to:

- View booking
- Add to calendar
- Return to discover

---

# 16. Reviews

Reviews should feel trustworthy.

Display the overall rating prominently.

Example:

★ 4.8

128 reviews

Use individual review cards with:

- Rating
- Review text
- Reviewer name
- Date

Avoid making reviews visually overwhelming.

---

# 17. Stylist Dashboard

The stylist dashboard can be more functional than the customer-facing experience.

It should still be clean and polished.

Stylists should be able to see:

- Upcoming bookings
- Recent reviews
- Profile views
- Booking activity

Keep the dashboard simple.

Do not make it look like a complicated enterprise admin panel.

---

# 18. Stylist Profile Management

Stylists should be able to easily edit:

- Name
- Bio
- Location
- Profile photo
- Portfolio
- Services
- Prices
- Availability
- Booking settings

Use clear forms with helpful labels.

Make image uploading easy on mobile.

---

# 19. Empty States

Empty states should feel intentional rather than broken.

Examples:

No search results:

"Couldn't find the right stylist"

"Try changing your location or filters."

No bookings:

"No upcoming appointments"

Your bookings will appear here.

---

# 20. Loading States

Use polished skeleton loaders where appropriate.

Avoid showing blank screens while data loads.

Loading states should resemble the final content layout.

---

# 21. Error States

Errors should be clear and helpful.

Avoid technical messages such as:

"500 Internal Server Error"

Instead use:

"Something went wrong"

"Please try again."

Provide a clear action where possible.

---

# 22. Images

Images are extremely important to this product.

Prioritise:

- High-quality stylist photography
- Consistent aspect ratios
- Good cropping
- Rounded image corners where appropriate

Do not distort images.

Use object-fit/cropping intelligently.

Avoid generic stock imagery wherever real stylist photography can be used.

---

# 23. Desktop Behaviour

Although mobile is the priority, desktop should feel intentional.

On larger screens:

- Use wider content containers
- Increase image/grid layouts
- Use multi-column stylist cards where appropriate
- Maintain comfortable whitespace
- Avoid stretching content across the entire screen

Do not simply enlarge the mobile UI.

---

# 24. Accessibility

The interface should be accessible.

Use:

- Adequate colour contrast
- Visible focus states
- Proper labels
- Semantic HTML
- Accessible buttons
- Adequate touch targets
- Alt text for meaningful images

Do not rely on colour alone to communicate important information.

---

# 25. Design Consistency

Create reusable components for:

- Buttons
- Cards
- Inputs
- Search bars
- Filters
- Ratings
- Navigation
- Modals
- Booking components
- Review components

Do not create slightly different versions of the same component on every page.

The entire application should feel like one coherent product.

---

# 26. Things to Avoid

Do NOT make the application look like:

- A generic SaaS dashboard
- An admin panel
- A template website
- An overly colourful social network
- A cluttered directory
- A website filled with unnecessary cards

Avoid:

- Excessive gradients
- Excessive animations
- Excessive shadows
- Tiny text
- Too many colours
- Too many competing buttons
- Unnecessary popups
- Overly complicated navigation
- Dense information layouts

---

# 27. Product Priority

When making design decisions, prioritise:

1. Finding a stylist
2. Understanding whether they are suitable
3. Seeing their work
4. Trusting their reviews
5. Checking price and availability
6. Booking quickly

Every screen should support this journey.

---

# 28. Implementation Rule

Before making significant UI changes, inspect the existing application and reuse existing components where possible.

Do not unnecessarily rewrite working functionality.

Do not change the database architecture or business logic purely for visual reasons.

Do not add features that are not specified.

When there is a design conflict, prioritise:

1. Usability
2. Mobile experience
3. Accessibility
4. Visual consistency
5. Visual polish

The goal is a **premium, trustworthy stylist marketplace that feels simple enough for anyone to use.**
